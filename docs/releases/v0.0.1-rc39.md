# v0.0.1-rc39

Runtime, diagnostics, and terminal-UX qualification over rc38. No model,
prompt, controller, KV, cache, or report-architecture behaviour change; the
release consolidates already-qualified post-rc38 work and adds this note plus
the AGENTS.md entry.

Qualified production code: `a526c3622a32dcf7102a35f817851e513e42e9bb`

Orbit remains CPU-first (`gpu_layers=0`); there is no GPU integration.

## Highlights

### Server startup profile (auto-calibration)
- The native server resolves a measured startup profile for the machine it runs
  on instead of shipping one host's fixed numbers, with a precedence chain
  (explicit CLI > `ORBIT_*` env > user profile > cached measured profile >
  bounded calibration at startup > conservative heuristic). Calibration measures
  on warm weights and prefers fewer threads within noise; a stale cache entry is
  re-evaluated rather than trusted.

### Deterministic zero-action analysis / report correctness
- An empty PLAN is asked once more when the runtime has already decoded
  something, rather than terminating prematurely.
- A zero-action deterministic run now renders its full report (decoded body,
  stage digest, verified indicators) instead of only a stop reason.

### Diagnostics / observability
- `/props` publishes the Ornith route-prefix reuse status and refusal reason
  alongside the existing Qwen states, so a reuse refusal is observable.

### Terminal / CLI UX
- `orbit server` colours only the model availability status (AVAILABLE green,
  MISSING red) in the interactive model list, width-safe and honouring
  `NO_COLOR` / non-TTY (raw text off a terminal).
- `orbit server --show-profile` reports the profile for the model a real start
  would use (explicit, interactive selection, or default), read-only, and names
  the model instead of silently previewing a generic heuristic.
- Final Markdown analysis reports render structure (headings, bold, inline code,
  lists, verbatim fenced code) only in the interactive terminal; `report.text`
  stays byte-identical Markdown for API, files, sessions, redirects and non-TTY.

### Internal structure (no behaviour change)
- The read-only status/metrics accessors moved to `native_llama/client_status.py`
  behind thin, byte-identical delegates (first step of an open runtime
  decomposition; the remaining target responsibilities were confirmed already
  owned by their dedicated modules).

## Technical stops (user-relevant)
- Intel `xe` iGPU (Vulkan) benchmarking is a standing TECHNICAL_STOP: decode is
  ~3x slower than the qualified CPU path and partial offload is thermally
  infeasible on the reference laptop. Orbit stays CPU-only.

## Analysis capability (unchanged from rc38)
- Static, sandboxed, network-denied deterministic deobfuscation and Office/OLE–VBA
  analysis over the frozen six-sample malware corpus; no execution, no retrieval.
