## Verified Identity

The profile is authorized only when the loaded GGUF matches the reviewed
metadata and protocol identity, including:

- architecture `qwen3moe`;
- model identity `Qwen3-Coder-30B-A3B-Instruct`;
- `general.file_type=15` (`Q4_K_M`);
- GPT-2/Qwen2 tokenizer metadata;
- the qualified expert layout;
- embedded-template SHA-256
  `87710339d25b4e789c1d723f93c91ee861a86d305bb3d20a845536f251d6ea8a`.

Filename matching alone never authorizes the profile. A modified template,
different architecture, incompatible tokenizer, different quantization, or
unknown Qwen3-Coder variant fails before inference rather than falling back to
the Qwen 3.6 or Gemma protocol.

## Protocol And Artifacts

The verified profile supports normal chat, structured routing, native XML tool
calls, tool-result/history serialization, post-tool finalization, existing-file
modification, and coding/tool workflows.

For generative `write_artifact`, Qwen3-Coder uses a constrained JSON-string
transport in its model-specific content phase. The backend performs only
structural framing and strict decoding. It does not strip whitespace, normalize
newlines or Unicode, repair content, retry silently, or synthesize task bytes.
Malformed framing, invalid UTF-8, unexpected termination, and
`finish_reason=length` fail closed before publication.

The shared RC27 artifact lifecycle remains authoritative: content must pass its
token, byte, UTF-8, path, and lifecycle checks before atomic publication. The
ephemeral `verify_artifact` capability remains target-bound and read-only.
Publication evidence now distinguishes `created` from `replaced`, so overwrite
authorization is not reported as an overwrite when no prior file existed.

The native sampler correction is restricted to the verified Qwen3-Coder path;
Gemma and Qwen 3.6 sampler behavior is unchanged.

## Performance Notes

On the qualification host with CPU-only inference, context 8,192, six main and
batch threads, batch 256, ubatch 128, temperature zero, thinking disabled, and
MTP disabled, Qwen3-Coder measured approximately:

- 18.8 tok/s synthetic long-prefill throughput;
- 11.35 tok/s synthetic medium-decode throughput;
- 31.1 GiB synthetic peak RSS;
- 28.16 tok/s median prefill in the production corpus;
- 8.16 tok/s median decode in the production corpus;
- 31.24 GiB production peak RSS.

The synthetic and workflow measurements exercise different prompt and output
shapes and are not directly interchangeable. The production corpus contains
many short generations. These values are descriptive local measurements, not
portable guarantees or marketing comparisons.

## Limits

- Support is restricted to the exact verified Qwen3-Coder profile above.
- Qwen3-Coder MTP and multimodal input are unsupported.
- Qwen 3.6 route-prefix checkpoints are not reused by Qwen3-Coder.
- Generative `write_artifact` does not provide an arbitrary exact-copy
  guarantee for externally authoritative bytes.
- Empty artifacts remain unsupported.
- The shared artifact scope remains one bounded UTF-8 text artifact per
  request, with no binary output or hidden multi-file project planning.
- Model-driven tool and artifact selection is not a universal completion
  guarantee.
