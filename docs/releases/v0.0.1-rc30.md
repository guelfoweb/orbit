# v0.0.1-rc30

Orbit Qualification Harness v1, recoverable transient native capability
discovery, and fail-closed full-document intent recognition. Production
runtime and backend behavior remain independent of the qualification package.

## Summary

- Add a small Python-first qualification layer that observes existing Orbit
  runtime and backend paths without becoming a second runtime.
- Enforce correctness and parity before optimization performance is reported.
- Add deterministic agentic workflow, lifecycle/failure, and full-document
  capability suites.
- Recover when native `/props` discovery fails transiently during startup,
  allowing a later operation to discover native capabilities and use an
  already-prewarmed checkpoint.
- Recognize the qualified missing full-document read phrasing while preserving
  inert-text masking and oversized-document fail-closed behavior.

## Qualification Harness V1

The harness uses strict versioned JSON fixtures and canonical `PASS`, `FAIL`,
`TECHNICAL_STOP`, and `NOT_APPLICABLE` results. It records authoritative
existing token, timing, filesystem, artifact, state-reuse, lifecycle, and Linux
server-process RSS evidence. Missing metrics remain unavailable; TTFT is not
estimated.

The v1 suites cover:

- common chat, exact route, tool-plus-final, and generative artifact workflows;
- deterministic bug-fix-and-test, existing-file modification, and failed-command
  recovery outcomes;
- same-model baseline/candidate comparisons for route-prefix reuse and prewarm;
- reset invalidation, cancellation, restore fallback, bounded RSS stability,
  and teardown cleanup;
- oversized, fit-capable, and inert full-document behavior.

Optimization comparisons run baseline and candidate in isolated processes and
require equivalent route, ordered tools, typed arguments, finish reason, and
deterministic outcomes before reporting wall-time changes. Valid cache reuse may
redistribute input work between evaluated and cached tokens. Invalid parity
suppresses performance deltas. Stable hardware identity remains gating, while
volatile available RAM is retained only as descriptive provenance.

Cross-model qualification compares declared capability outcomes rather than
wording, token counts, or model strategy. There is no LLM judge, universal
score, cross-model performance ranking, scheduler, plugin framework, or second
model registry. `NativeModelProfile` remains the capability authority, and no
production module imports `orbit.qualification`.

## Native Capability Discovery

A client that reached the server before startup prewarm/readiness could see a
transient `/props` failure and previously cache a permanent non-native result.
That false negative omitted the Qwen route-prefix anchor even after the server
became ready.

Transport, timeout, and startup/server failures now remain uncached and are
retried only on a later normal operation. Successful native responses and
confirmed non-native responses remain cached. Malformed successful responses
remain fail-closed. The change adds no background polling, retry loop, per-token
discovery, or checkpoint/prewarm behavior change.

Real Qwen3-Coder validation retained the prewarmed checkpoint, recovered native
capability discovery, restored the 768-token route prefix, and reported zero
fallbacks.

## Full-Document Safety

The full-document intent matcher now recognizes the qualified wording `read
whole the text document`. It reuses existing masking for quoted, fenced, and
structured inert text instead of adding semantic routing or a second parser.
Partial reads, literal/concept search, pagination, path confinement, and
no-mutation behavior remain separate.

If a requested document cannot fit the active context, Orbit performs the
normal preflight and fails closed. It reports no document coverage and the
required/available context without presenting a partial prefix as complete or
falling back to blind content analysis. Fit-capable documents retain complete
analysis and snapshot cleanup.

The end-to-end qualification suite passed 3/3. At context 8,192 the qualified
oversized fixture required 47,477 tokens and recorded `coverage=none`; the fit
fixture recorded `coverage=complete`, and inert full-document wording did not
trigger preflight.

## Limits

- The harness currently uses bounded deterministic fixtures, not broad model
  scoring or statistical benchmarking.
- TTFT remains unavailable unless authoritative instrumentation is added later.
- Performance comparisons are same-model only and valid only after operational
  parity.
- Capability absence produces `NOT_APPLICABLE`; it is not a model failure.
- The oversized document fixture is bound to context 8,192. It intentionally
  ceases to be oversized when available context can admit its roughly
  47,000-token requirement.
- Full-document phrase coverage is deliberately narrow and is not a general
  multilingual semantic classifier.
- Qwen3-Coder MTP and multimodal input remain unsupported.
