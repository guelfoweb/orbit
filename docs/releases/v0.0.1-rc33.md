# v0.0.1-rc33

Compact terminal operation, deterministic slash commands, authoritative live
metrics, and qualified Qwen3-Coder cache and low-memory behavior.

## Highlights

- Simplify the interactive transcript with a compact banner, tool events,
  activity line, and scoped footer while preserving streamed Markdown and
  deterministic non-TTY output.
- Add deterministic `/read`, `/search`, `/ls`, and `/models` commands using the
  existing safe acquisition, search, listing, and model-discovery paths.
- Report authoritative live prefill and decode progress without estimating
  unknown totals or adding model calls, prompt tokens, or polling loops.
- Preserve the immutable Qwen3-Coder route checkpoint across the exact internal
  chat/tools cache-mode transition while retaining explicit lifecycle safety.
- Refresh the supported-model performance table from repeated measurements on
  the documented NUC10 host.
- Add opt-in backend-owned MoE expert-usage diagnostics with no routing effect.
- Add the verified Qwen3-Coder `--low-memory` mode and interactive Standard/Low
  memory selection. On the qualified host, peak RSS fell by about 41.6%, from
  31.3 GiB to 18.3 GiB; Standard remains the default.
- Add exact `backend_ttft_ms` and `stream_ttft_ms` metrics, keeping backend token
  production distinct from client-visible streaming latency.

RC33 contains squash merges from PRs #180 through #190. RC32 remains the
published predecessor.

## Limits

- Performance and memory measurements are specific to the documented hardware,
  model files, backend build, and workloads.
- Qwen3-Coder low-memory mode is opt-in and supported only for the exact verified
  profile; 24 GB is the recommended practical minimum complete-host RAM.
- MoE expert telemetry is diagnostic, disabled by default, and cannot influence
  model routing.
- `backend_ttft_ms` and `stream_ttft_ms` are distinct; neither includes model
  startup or predicts completion time.
