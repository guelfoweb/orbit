# v0.0.1-rc32

Zero-setup interactive native-server startup. Running `orbit server` in a TTY
now discovers supported models, permits a verified selection, and can download
a missing verified model before starting it.

## Summary

- Add verified startup model discovery without loading model weights.
- Add numeric selection for available and missing verified models.
- Reuse the existing Orbit downloader for confirmed missing-model downloads.
- Require the canonical download destination and exact normal profile
  verification before server startup.
- Keep explicit `--model`, explicit `--model-id`, non-TTY startup, and direct
  `orbit download` behavior unchanged.

RC32 contains squash merges `a474614` from PR #177, `92aae65` from PR #178,
and `0c394d8` from PR #179. RC31 remains the published predecessor.

## Interactive Startup

The recommended interactive entry point is:

```bash
orbit server
```

Orbit performs one bounded metadata-only discovery pass and displays available,
missing, unsupported, and unverified models. Only `AVAILABLE + VERIFIED` and
`MISSING + VERIFIED` rows are selectable. Unsupported or unverified GGUFs are
shown only for information and cannot be promoted by filename or registry
metadata.

Selecting an available verified model passes its exact path, manifest identity,
profile, mmproj, and MTP metadata through the normal server bootstrap and
profile-verification path.

Selecting a missing verified model shows its canonical download target and asks
`Download now? [Y/n]`. Acceptance calls the existing `download_model()` path,
preserving its integrity, resume, interruption, and temporary-file behavior.
After download, Orbit requires the expected canonical destination, rediscovers
that exact file, verifies the requested model identity, and runs normal exact
profile detection before bootstrap.

Decline, EOF, interruption, download failure, malformed content, wrong profile,
unexpected destination, verification failure, or bootstrap failure never starts
another model and never enters a reselection or download loop.

## Limits

- Interactive selection and download require a TTY; headless startup remains
  explicit and non-interactive.
- Orbit never silently chooses a model.
- Downloads can be large and remain dependent on network and local storage.
- Only registry-declared download targets for currently verified profiles are
  offered. Exact profile detection, not the registry or filename, authorizes
  startup.
