# v0.0.1-rc25

Deterministic long-document display, search, and full-analysis admission.

## Summary

- Display or export long UTF-8 files through exact bounded pages without
  asking the model to reproduce their contents.
- Scan complete stable snapshots for exact literal terms with deterministic
  counts and line evidence.
- Search concepts through a bounded multilingual plan and exact source
  windows while preserving conservative negative-answer semantics.
- Admit full-document analysis only when the production tokenizer proves that
  the complete rendered request fits with the output reserve and safety
  margin.
- Report complete, partial, or no file visibility explicitly instead of
  presenting a prefix as the whole document.

## Document Paths

Exact display uses stable pagination with source byte and line ranges, file
size, and SHA-256 identity. Content is returned directly rather than generated
again by the model. Pages never imply complete model visibility unless the
whole verified snapshot was actually included.

Literal searches scan the complete snapshot internally with Unicode NFKC
normalization, case folding, optional whole-word matching, deterministic
window merging, exact line evidence, and complete match counts. They require
zero model calls. A definitive negative is limited to the requested literal
word or phrase.

Concept searches use one bounded planner to select translated terms and close
synonyms in at most three detected document languages, with at most twelve
terms total. Orbit scans the complete snapshot deterministically and gives one
verifier only the bounded exact windows that contain visible matches. A
lexical match is not automatically accepted as conceptual support.

When a concept search has no lexical match, Orbit performs one full-document
analysis only if exact tokenizer admission succeeds. Otherwise the answer
states that the searched terms produced no evidence but cannot exclude
indirect wording. There is no semantic chunking, map-reduce, RAG, embeddings,
shell search, or model-generated regex.

## Integrity And Coverage

Stable snapshots retain SHA-256, size, line count, descriptor-relative path
confinement, `O_NOFOLLOW`, regular-file checks, and inode/version
revalidation. File replacement, truncation, deletion, symlink races, invalid
UTF-8, and special files fail closed. Larger snapshots may use SSD-backed
storage and are cleaned on success, error, cancellation, timeout, reset, and
restart.

File visibility, scan coverage, and semantic coverage are reported
separately. Exact ranges identify every returned page or evidence window. A
complete lexical scan does not claim complete semantic understanding, and a
partial semantic result cannot produce a definitive conceptual negative.

The production tool schema and tool-mode prompt are unchanged. The accepted
Gemma 4 26B-A4B Q4_0 tool-mode baseline remains 708 tokens, a delta of zero.

## Limits

- Conceptual recall depends on the model-selected search terms.
- Plans are limited to twelve terms and three document languages.
- Arbitrarily large documents do not receive a fast complete semantic scan.
- Semantic chunking remains a technical stop because measured CPU wall time
  and cumulative prefill were incompatible with usable latency.
- No definitive conceptual negative is available unless full-document
  semantic coverage completes in one tokenizer-admitted call.
- UTF-8 snapshot limits and the active context size still bound supported
  full-document analysis.
