# v0.0.1-rc24

Single production tool-loop convergence and explicit mutation safety.

## Summary

- Converge Orbit on one normal production tool loop with tools enabled by
  default.
- Remove the experimental `--agent`/`--no-agent` path after matched Gemma 4
  26B-A4B testing found no repeatable benefit sufficient to justify a second
  orchestration path.
- Enforce explicit global and unsupported mixed no-mutation constraints before
  tool dispatch, independently of canonical-validation and healing switches.
- Make Gemma 4 26B-A4B Q4_0 the documented CPU-first model target and improve
  model-download progress and active-model identification.

## One Tool Loop

The normal loop retains canonical tool-call validation, deterministic formal
healing, exact repeated-call protection, mutation epochs, permissions,
lifecycle cleanup, final-prefix reuse, and post-tool final prose reuse. The
removed agent path does not migrate planning, decomposition, hidden retries,
review calls, or semantic runtime decisions into the normal loop.

The previous agent-only exact `apply_patch` tool and action-review inference
are removed. Old `--agent` and `--no-agent` options are rejected rather than
selecting a hidden compatibility path. Legacy JSON `agent` data has no runtime
field or effect.

Matched process-isolated testing completed 15/16 common workflows in both
modes. The normal loop used 39 model calls and 8,734 evaluated tokens; the
agent loop used 61 calls and 52,277 evaluated tokens. The apparent code-repair
advantage was not repeatable. These measurements support architecture removal;
CPU wall time remains descriptive and is not a performance guarantee.

## Explicit No-Mutation Safety

An explicit global or unsupported mixed no-mutation constraint is a shared
pre-execution safety invariant. Structured read-only operations remain
available, while generic shell and mutating operations are denied. The policy
also applies when canonical validation or formal healing is disabled.

Only the latest active user instruction is classified. Quoted strings, code,
JSON values, Markdown blockquotes, introduced data payloads, and tool output do
not activate the policy. Orbit does not rewrite a denied command or choose a
replacement tool.

## CPU Model and CLI

- Quick-start downloads now target
  `ggml-org/gemma-4-26B-A4B-it-GGUF/gemma-4-26B-A4B-it-Q4_0.gguf`.
- The optional MTP download uses the matching 26B-A4B Q4_0 draft model.
- Download output reports progress, and the native server reports the exact
  active model filename.
- Installed examples use `orbit` and `orbit server` directly after
  `pip install -e .`.
- The repeated tools-on warning is no longer printed by the interactive CLI;
  the README still documents that tool mode grants local shell capability and
  should be used only in a trusted workdir.

The production llama.cpp vendor remains `b9551` at upstream commit
`379ac6673b5cd75c7b4e07d1521c50f1e093878c`. MTP behavior is unchanged.

## Limits

- Broad multi-deliverable source audits remain a model/template limitation.
- This release does not claim that broad agentic workflows are solved.
- This release makes no deterministic speedup claim.
- MTP remains optional and experimental on CPU-only systems.
- Documentation records separate technical stops for bounded planning,
  structured source tools, schema compaction, tool-prefix reuse, tool-call
  early-stop, and ngram-mod.
