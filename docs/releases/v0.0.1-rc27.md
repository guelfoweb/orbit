# v0.0.1-rc27

Model-driven, atomic generation of bounded UTF-8 text artifacts for the
verified Qwen 3.6 profile and the existing Gemma path.

## Summary

- Add a small model-selected `write_artifact` request containing only path,
  overwrite, and parent-creation arguments.
- Generate file bytes in a dedicated content-only native phase without shell,
  JSON/XML tool envelopes, heredocs, or explanatory prose.
- Publish complete validated content atomically on the destination filesystem.
- Expose an ephemeral, target-bound, read-only `verify_artifact` capability
  only after publication.
- Preserve conservative path, lifecycle, no-mutation, and restart-recovery
  behavior without adding semantic routing or hidden retries.

## Artifact Protocol

The model decides whether an artifact is needed, its path and format, whether
parents may be created, whether an existing file may be overwritten, the exact
content, the verification check, and the final response. Orbit validates only
the structural request and safety constraints. It never infers task content,
chooses a filename, repairs generated bytes, or completes truncated output.

The content phase receives bounded task context and emits only UTF-8 file
content. It has no tools and its output is never parsed as a tool call. A
generation ending in `length`, timeout, cancellation, reset, backend error,
invalid UTF-8, or a size violation is not published.

After a stopped and valid generation, Orbit atomically publishes the file and
records its path, byte count, SHA-256, and publication status. Only then does
the model receive `verify_artifact`, which is bound to the exact published
artifact and accepts no alternate path. Verification performs bounded
read-only integrity or syntax checks and cannot invoke shell or mutate the
filesystem. The final model response receives both publication and
verification evidence.

## Atomicity And Recovery

Temporary content is private and located on the same filesystem as the target.
Path operations remain confined to the active workdir, do not follow symlinks,
reject special files, and revalidate parent and target identity immediately
before commit. New-file publication uses atomic no-replace semantics;
authorized overwrite uses the validated atomic replacement path. No partial
destination file is exposed.

Missing parents are created only when the model explicitly selects
`create_parents=true`. Orbit records exactly which parents it created and may
remove them on failure only while they remain empty with unchanged identity.
It never renames a shared parent tree, removes a pre-existing directory, or
moves concurrently created content into private state.

Restart recovery is deliberately conservative. Private state is removed only
after positive proof that its owner is inactive and all manifest, UID, boot,
inode, path, symlink, and workdir checks pass. Active and unknown owners are
always preserved. Age is diagnostic only and never authorizes deletion.
Malformed, ambiguous, mismatched, or symlinked residue is preserved for manual
inspection. Orbit therefore does not claim zero residue at every possible
power-loss instant.

## Limits

- One bounded UTF-8 text file per `write_artifact` request.
- Maximum 4,096 generated content tokens and 64 KiB after UTF-8 encoding.
- No binary artifacts and no hidden multi-file project planning.
- Tool selection remains model-driven; very small or overly broad requests may
  choose chat or an existing shell path instead.
- The runtime does not guarantee atomic publication of an entire shared
  directory tree.
- Unknown or ambiguous crash residue is preserved and may require manual
  inspection.
- Qwen support remains restricted to the exact verified
  `Qwen3.6-35B-A3B-Q4_K_M.gguf` profile. Qwen MTP and multimodal input remain
  unsupported.
