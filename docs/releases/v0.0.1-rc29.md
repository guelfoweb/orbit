# v0.0.1-rc29

Fail-closed native runtime-family loading and verified Qwen3-Coder route-prefix
reuse with synchronous startup prewarm. Routing remains model-driven, tools
remain enabled, and Gemma and Qwen 3.6 behavior stays isolated.

## Summary

- Reject incomplete, mixed, or escaping libllama/libggml runtime families
  before native mapping.
- Add a process-local route checkpoint only for the exact verified
  `orbit-qwen3-coder-native-v1` profile.
- Capture the unpadded 768-token checkpoint before server readiness, allowing
  the first real tools-on route to restore the stable prefix.
- Preserve the existing lazy cold-capture path when ordinary prewarm fails or
  startup prewarm is explicitly disabled.
- Keep Qwen 3.6 and Gemma checkpoint identities, rendering, and lifecycle
  behavior unchanged.

## Native Loader Hardening

Orbit validates the required dependency prefix in dependency-first order before
loading the requested native library. Missing or partial runtime dependencies
therefore fail before any member of that family is mapped.

Every required library must resolve to a regular file inside the selected
canonical runtime root. A dependency symlink that escapes that root is rejected.
The process then claims one canonical runtime family; a second, different root
cannot silently provide another libllama or libggml family. Canonical aliases of
the same root remain valid, repeated same-family loads remain supported, and the
loader does not mutate the global process environment.

## Qwen3-Coder Route Checkpoint

Route-prefix reuse is authorized only after the exact
`orbit-qwen3-coder-native-v1` profile has passed its existing metadata,
tokenizer, template, quantization, and expert-layout checks. Filename matching
alone cannot enable the checkpoint.

- checkpoint identity: `qwen3-coder-route-prefix-v1`;
- invariant route prefix: 789 tokens;
- checkpoint boundary: 768 tokens, without padding;
- serialized sequence state: 75,507,864 bytes;
- restored route accounting: `cached=768` plus the dynamic suffix.

The identity also binds model and file identity, tokenizer and template, route
system policy, tool schema, prefix hashes, backend revision, context, batch,
ubatch, threads, and checkpoint format. It is never shared with Qwen 3.6 or
Gemma.

Cold full prefill, explicit segmentation at token 768, capture, and restore
produced byte-identical logits with maximum absolute difference `0.0`. The next
token, ordered candidates, route, tool, typed arguments, visible output, and
finish reason remained identical across the validated chat, filesystem,
failure, inert-payload, artifact, and existing-file workflows.

Disable Qwen3-Coder route checkpoint capture and restore immediately with:

```bash
ORBIT_QWEN3_CODER_ROUTE_PREFIX_REUSE=0 orbit server ...
```

Invalid values disable reuse safely. The switch does not affect Qwen 3.6 route
reuse, Gemma final-prefix reuse, or Gemma MTP.

## Startup Prewarm

With native tools enabled, the server synchronously captures the existing
Qwen3-Coder checkpoint after model/profile verification and before constructing
and binding the HTTP server. Prewarm performs no sampling and includes no user
tokens. The first real request restores the checkpoint rather than capturing it.

Partial prefill, cancellation, or failed serialization cannot publish a
checkpoint. Ordinary capture failures remain diagnostic and leave the safe lazy
cold-capture path available without a startup retry loop. SIGINT during prewarm
cancels capture and exits with code 130 before the server binds.

Disable only startup prewarm while retaining lazy route reuse with:

```bash
ORBIT_KV_PREFIX_PREWARM=off orbit server ...
```

Reset invalidates the checkpoint. The next eligible route evaluates and
captures the prefix cold; later routes restore normally. Checkpoints remain
process-local and are not portable across processes, models, templates, or
runtime configurations.

## Performance Notes

Representative local CPU-only post-merge measurements used context 8,192, six
main and batch threads, batch 256, ubatch 128, temperature zero, thinking off,
MTP off, and tools on:

- cold first route: about 24.40 seconds prefill and 25.09 seconds route wall;
- restored first route: about 1.49 seconds prefill and 2.10 seconds route wall;
- first greeting end-to-end: about 28.97 seconds without startup prewarm and
  9.10 seconds with startup prewarm;
- restored prefix: 768 cached tokens, with 32 dynamic tokens in the measured
  greeting route;
- startup capture: typically about 23.85-24.36 seconds;
- one measured model-load plus prewarm server-ready run: about 44.16 seconds;
- checkpoint size: 75,507,864 bytes;
- measured ready-state RSS increase: about 91.6 MB.

The prefill work is shifted to startup, not removed. Timings depend on hardware,
memory pressure, configuration, and workload; they are descriptive rather than
portable guarantees. Repeated restores and reset/capture cycles showed no linear
RSS growth.

## Limits

- Startup is slower because route-prefix capture completes before readiness.
- The Qwen3-Coder checkpoint is process-local and configuration-bound.
- Reset causes the next eligible route to recapture cold.
- Prewarm optimizes route prefill only; it does not accelerate final generation
  or tool execution.
- Qwen3-Coder MTP and multimodal input remain unsupported.
- Qwen 3.6 checkpoints are not reused by Qwen3-Coder.
- Tools remain enabled and route selection remains model-driven; no
  deterministic CHAT bypass or prompt-specific shortcut is present.
